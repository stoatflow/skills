## `stoatflow`

| Key | Type | Default | Description |
|---|---|---|---|
| `stoatflow.application-id` | string |  | Unique identifier for this application. Used for consumer group and transactional ID. |
| `stoatflow.bootstrap-servers` | string | `localhost:9092` | Kafka bootstrap servers (comma-separated list). |
| `stoatflow.lanes.count` | integer | `max(2, CPU cores)` | Number of lanes for parallel processing. Each lane is a virtual thread that processes events for a subset of keys. Default: max(2, CPU cores). Higher values increase per-key parallelism at the cost of more queues and lane-dispatch overhead. |
| `stoatflow.lanes.queue-capacity` | integer | `300` | Capacity of each lane's queue. Controls backpressure - when full, the dispatcher blocks until space is available. |
| `stoatflow.lanes.thread-type` | enum | `VIRTUAL` | Thread type for lane threads. VIRTUAL: Project Loom virtual threads (default — FFM backend eliminates JNI pinning). PLATFORM: OS threads, use with JNI backend if pinning is a concern. One of: PLATFORM, VIRTUAL. |
| `stoatflow.commit-barrier.interval-ms` | integer | `500` | Seed interval between commit barriers in milliseconds. Used as the initial interval before post-commit scheduling adjusts it. |
| `stoatflow.commit-barrier.timeout-ms` | integer | `60000` | Timeout for commit barrier completion in milliseconds. Bounds every .join()/.get() on the commit critical path via BoundedAwait. Also cascades to Kafka producer transaction.timeout.ms, max.block.ms, and delivery.timeout.ms via forced overrides. Must be greater than interval-ms. |
| `stoatflow.commit-barrier.dedicated-commit-thread` | boolean | `true` | Whether to use a dedicated platform thread for commit barrier execution. When enabled, commits run on a separate thread instead of inline on the last lane thread, preventing lane stalls during Kafka transaction commit and RocksDB epoch flush. |
| `stoatflow.commit-barrier.interval-factor` | number | `1.5` | Barrier interval as a multiple of estimated commit duration. 1.0 = back-to-back commits (interval equals commit time). 1.5 = interval is 1.5x commit time. |
| `stoatflow.commit-barrier.min-interval-ms` | integer | `150` | Minimum barrier-to-barrier interval in milliseconds (wall-clock time from barrier N creation to N+1 creation). |
| `stoatflow.commit-barrier.max-interval-ms` | integer | `5000` | Maximum barrier-to-barrier interval in milliseconds. |
| `stoatflow.commit-barrier.idle-interval-ms` | integer | `30000` | Idle-throttle interval in milliseconds (ADR-134). When a warm-idle EOS app produces 5+ consecutive empty epochs, the barrier scheduler parks this long between empty commits instead of the min-interval-ms floor (~200x less idle transaction churn). The cadence snaps back with no added latency as soon as real work reappears. Effective value is clamped to min(idle-interval-ms, timeout-ms/2) at engine start (WARN on clamp). EOS-only. Set to 0 to disable the throttle (restores pre-ADR-134 behavior). |
| `stoatflow.commit-barrier.commit-duration-ema-alpha` | number | `0.15` | Commit duration EMA smoothing factor. Higher values make the estimate more responsive to recent samples, lower values produce smoother estimates. Controls how quickly the barrier scheduler adapts to changes in commit duration. |
| `stoatflow.commit-barrier.max-epoch-records` | integer |  | Hard cap on records dispatched per epoch. When set, limits the S1 feedback controller output to prevent unbounded epoch growth. Smaller values reduce producer flush time at commit but increase commit frequency. Unset = no hard limit. |
| `stoatflow.commit-barrier.initial-max-epoch-records` | integer | `4096` | Initial cap on records dispatched per epoch before the S1 feedback controller has learned the topology's memory profile. Only affects the first epoch(s) after startup — subsequent epochs are governed by S1 (ADR-091/ADR-107). Set to -1 to disable. |
| `stoatflow.commit-barrier.memory-cap-ema-alpha` | number | `0.1` | EMA smoothing factor for the memory-based epoch size cap. Controls how quickly the feedback controller adapts to changes in per-record state size. Lower values smooth more aggressively. |
| `stoatflow.commit-barrier.epoch-records-ema-alpha-grow` | number | `0.3` | EMA smoothing factor for the epoch records safety cap on the GROW path (S1 binding-aware update, ADR-107). Used when a binding signal fires (RECORD_COUNT, MEMORY_PRESSURE, dispatcher stall, or soft binding) or when the natural rate is rising. Higher values react faster to growth. |
| `stoatflow.commit-barrier.epoch-records-ema-alpha-decay` | number | `0.05` | EMA smoothing factor for the epoch records safety cap on the DECAY path (S1 binding-aware update, ADR-107). Used only when no binding signal fired and the natural rate is declining. Lower values resist transient drops more strongly. |
| `stoatflow.commit-barrier.capped-growth-factor` | number | `1.3` | Multiplicative growth floor on smoothedEpochRecords whenever the cap was binding this epoch (ADR-107). Guarantees monotonic growth out of a collapsed equilibrium independently of the alpha-driven EMA update. Set to 1.0 to disable. |
| `stoatflow.commit-barrier.soft-binding-ratio` | number | `0.9` | Soft-binding threshold for the S1 feedback controller (ADR-107). On TIME-triggered epochs, the cap is treated as effectively binding when actual/cap >= ratio, even though the dispatcher did not literally hit the RECORD_COUNT threshold. Lower values widen what counts as binding (more eager grow). Set > 1.0 to disable soft binding entirely. |
| `stoatflow.commit-barrier.process-latency-ema-alpha` | number | `0.1` | EMA smoothing factor for per-record process latency (rate-based cap). Lower than epoch-records-ema-alpha-grow to resist outliers from filtered records. |
| `stoatflow.commit-barrier.duration-ema-alpha` | number | `0.3` | EMA smoothing factor for barrier duration overrun ratio. Controls how quickly the duration-based throttle reacts to barrier intervals exceeding max-interval-ms. |
| `stoatflow.commit-barrier.min-epoch-records-factor` | number | `0.5` | Minimum epoch records factor for the S1 safety cap floor. Prevents maxEpochRecords from dropping below a fraction of the recent epoch average (smoothedEpochRecords × factor). Stabilizes epoch sizes for heterogeneous workloads. Set to 0.0 to disable. |
| `stoatflow.commit-barrier.max-engine-restarts` | integer | `5` | Maximum number of fault-triggered in-place engine restarts (ADR-127) permitted within a rolling engine-restart-window-ms window before the instance escalates to a terminal shutdown (mirrors Kafka Streams bounding REPLACE_THREAD). Only error-motivated (abort) restarts consume this budget; programmatic / HA-demote graceful restarts do not. Set to 0 to disable in-place restart recovery (every fatal processing/production fault shuts the instance down). |
| `stoatflow.commit-barrier.engine-restart-window-ms` | integer | `300000` | Rolling window in milliseconds over which max-engine-restarts fault-triggered engine restarts are counted (ADR-127). A recurring/deterministic fault crashing every epoch is bounded to max-engine-restarts restarts within this window, then the instance shuts down rather than looping. |

| `stoatflow.state.format-downgrade` | enum | `refuse` | What to do when a store's on-disk format is newer than the topology asks for — today, a headers-aware store (KIP-1271) opened with record headers turned off. refuse (default) fails startup with an actionable message and touches nothing on disk, so an accidental flag flip costs a restart rather than data. wipe-and-restore acknowledges the downgrade: the affected store's local state is deleted and rebuilt from its changelog (one full restore, bounded by changelog size). | `stoatflow.ha.promotion-settle-window-ms` | integer | `500` | Pre-fence election-token settle window (multi-standby N>2 leader election). | `stoatflow.ha.desired-standbys` | integer | `1` | Desired number of passive standbys (multi-standby N>2 election). Default 1 = today's N=2 pair (one active + one standby). Drives the readiness redundancy floor (an active reports 'redundancy below desired' when it has fewer than this many caught-up standby spares) and the ha.redundancy.ready-standbys / ha.redundancy.below-desired metrics. Must be in 0..max-standbys. |
| `stoatflow.ha.max-standbys` | integer | `3` | Hard ceiling on the number of standbys, bounding K-times changelog fan-out (each standby runs its own continuous changelog reader = K-times broker read + K-times local storage). Default 3 = K <= 4 total. Cascaded/shared replication is future-scoped; this cap is the trigger to revisit. |
| `stoatflow.ha.failover-priority` | integer | `0` | Per-pod failover-placement hint (multi-standby election). Never overrides lag (the election is lag-primary) nor the skew-invariant hash floor — it only breaks equal-lag ties. Default 0 (neutral). |
